01 What is Exception?

An Exception is an unwanted event that interrupts the normal flow of a program during execution.

Strong interview point: Errors are generally unrecoverable while Exceptions can usually be handled. 
System.out.println("Start");

int a = 10 / 0;

System.out.println("End");

The program crashes because ArithmeticException occurs.

04 try-catch-finally

try {
    int a = 10 / 0;
}
catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero");
}
finally {
    System.out.println("finally always executes");
}
finally block executes whether exception occurs or not. Used for cleanup like closing DB connection/files.

Multiple Catch

try {
    String s = null;
    System.out.println(s.length());
}
catch (ArithmeticException e) {
    System.out.println("Arithmetic");
}
catch (NullPointerException e) {
    System.out.println("Null");
}

06 Custom Exception

class InvalidAgeException extends Exception {

    public InvalidAgeException(String msg){
        super(msg);
    }
}

public class Test {

    static void checkAge(int age)
            throws InvalidAgeException {

        if(age < 18){
            throw new InvalidAgeException(
                "Age must be 18+"
            );
        }

        System.out.println("Eligible");
    }
}
Custom exceptions are heavily asked in Spring Boot and banking project interviews.

07 try-with-resources

Introduced in Java 7 to automatically close resources. 

try(
    BufferedReader br =
        new BufferedReader(
            new FileReader("abc.txt")
        )
){
    System.out.println(br.readLine());
}
catch(IOException e){
    e.printStackTrace();
}
Resource must implement AutoCloseable interface.

08 Important Interview Questions

Q1 What is the difference between Error and Exception?
Exception can usually be handled and recovered from, whereas Error represents serious JVM/system-level problems like OutOfMemoryError and StackOverflowError.
Q2 Difference between Checked and Unchecked Exception?
Checked exceptions are checked at compile time and must be handled using try-catch or throws. Unchecked exceptions occur at runtime and handling is optional.
Q3 What is the difference between throw and throws?
throw is used to explicitly throw an exception object, while throws is used in method signatures to declare possible exceptions.
Q4 Can finally block skip execution?
Yes. finally may not execute in cases like System.exit(), JVM crash, or power failure.
Q5 Can we write try block without catch block?
Yes, but it must be followed by finally block. try alone is invalid.
Q6 Can we have multiple catch blocks?
Yes. Multiple catch blocks are allowed, but child exceptions must come before parent exceptions otherwise compile-time error occurs.
Q7 Why child exception catch must come before parent exception?
Because parent catch block can already handle child exceptions, making child catch unreachable.
Q8 What happens if exception occurs and no catch block handles it?
JVM's default exception handler terminates the program and prints stack trace.
Q9 What is stack trace?
Stack trace shows exception type, message, and sequence of method calls where exception occurred.
Q10 Difference between final, finally and finalize?
final is keyword, finally is block used in exception handling, and finalize() is method called by garbage collector before object destruction.
Q11 Can we catch Error?
Technically yes, but generally not recommended because Errors indicate critical JVM issues.
Q12 What is custom exception?
User-defined exception created by extending Exception or RuntimeException classes for business-specific validation.
Q13 Why checked exceptions exist in Java?
To force developers to handle recoverable situations like file handling or database connectivity.
Q14 What is try-with-resources?
Introduced in Java 7 to automatically close resources that implement AutoCloseable interface.
Q15 Can constructor throw exception?
Yes. Constructors can throw exceptions using throws keyword and object creation fails if exception occurs.
