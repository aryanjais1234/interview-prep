01 What is Collection Framework?

Java Collection Framework is a unified architecture of interfaces, classes, and algorithms designed to store, retrieve, manipulate, and communicate groups of objects dynamically.

Why Was It Needed? – Array Problems

❌ Problems with Arrays
• Fixed size — can't grow/shrink
• No built-in add/remove methods
• Difficult insertion/deletion (shifting)
• No sorting/searching support
• Can't hold only unique elements
• Can't use key-value pairs
✅ Collection Framework Solves
• Dynamic size — grows/shrinks automatically
• Ready-made add/remove/search methods
• Efficient insertion/deletion
• Built-in sorting & searching
• Set enforces uniqueness
• Map supports key-value pairs 
// Arrays — fixed, painful
int[] arr = new int[5];
// can't add 6th element — stuck!

// Collections — dynamic, powerful
List<Integer> list = new ArrayList<>();
list.add(1); list.add(2); list.add(3); // grows automatically
list.remove(0);                         // built-in remove
Collections.sort(list);                  // built-in sort

02 Collection Hierarchy

java.lang.Iterable
└── java.util.Collection (root interface)
├── List – ordered, index-based, duplicates allowed
├── ArrayList   – dynamic array
├── LinkedList  – doubly linked list
├── Vector      – synchronized, legacy
└── Stack       – LIFO, extends Vector
├── Set – unique elements, no index
├── HashSet       – unordered, O(1)
├── LinkedHashSet  – insertion order
└── TreeSet       – sorted, O(log n)
└── Queue – FIFO ordering
├── PriorityQueue – min-heap by default
└── ArrayDeque   – double-ended queue
java.util.Map (separate hierarchy — NOT extends Collection)
├── HashMap        – unordered, O(1), null allowed
├── LinkedHashMap  – insertion/access order
├── TreeMap        – sorted keys, O(log n)
└── Hashtable     – synchronized, legacy, no null
📌 Key fact: Map does NOT extend Collection. It is a completely separate hierarchy. This is a very common interview trap.

05 ArrayList – Deep Internal Working

Internal Structure

// ArrayList internally uses an Object array
transient Object[] elementData;    // backing array
private int size;                  // actual element count

// Default initial capacity = 10
private static final int DEFAULT_CAPACITY = 10;

Capacity Growth Formula

// When array is full, ArrayList grows by ~1.5x
int newCapacity = oldCapacity + (oldCapacity >> 1);
// Example: 10 → 15 → 22 → 33 → 49...

// Internally a new array is created and System.arraycopy() is called
elementData = Arrays.copyOf(elementData, newCapacity);

Complexity

OperationComplexityWhy
get(index)O(1)Direct array access
add(element) at endO(1) amortizedAppend to array end
add(index, element)O(n)Elements must shift right
remove(index)O(n)Elements must shift left
contains()O(n)Linear search
Resize (grow)O(n)Array copy to new array

Full Example

import java.util.*;

public class ArrayListDemo {
    public static void main(String[] args) {

        List<String> list = new ArrayList<>();

        list.add("Alice");
        list.add("Bob");
        list.add("Charlie");
        list.add("Alice");   // duplicate allowed

        System.out.println(list);              // [Alice, Bob, Charlie, Alice]
        System.out.println(list.get(1));       // Bob
        System.out.println(list.size());       // 4

        list.remove("Bob");
        System.out.println(list);              // [Alice, Charlie, Alice]

        // Sort
        Collections.sort(list);
        System.out.println(list);              // [Alice, Alice, Charlie]
    }
}
⚠️ ArrayList is NOT thread-safe. For thread safety use Collections.synchronizedList() or CopyOnWriteArrayList.

06 Why Integer not int? – Generics, AutoBoxing & Unboxing

Java Generics only work with reference types (Objects), not primitive types. This is because generics use type erasure — at runtime all generics become Object.

ArrayList<int> list = new ArrayList<>();   // ❌ Compilation Error!
ArrayList<Integer> list = new ArrayList<>(); // ✅ Correct

Wrapper Classes

PrimitiveWrapper ClassExample
intIntegerInteger.valueOf(10)
doubleDoubleDouble.valueOf(3.14)
charCharacterCharacter.valueOf('A')
booleanBooleanBoolean.valueOf(true)
longLongLong.valueOf(100L)

AutoBoxing – Automatic primitive → wrapper

List<Integer> list = new ArrayList<>();
list.add(10);   // you write int literal
// Compiler converts to: list.add(Integer.valueOf(10)); — AutoBoxing

int x = list.get(0);
// Compiler converts to: int x = list.get(0).intValue(); — Unboxing

AutoBoxing Trap – NullPointerException

List<Integer> list = new ArrayList<>();
list.add(null);

int x = list.get(0);   // ❌ NullPointerException!
// null.intValue() → NPE during unboxing

Integer Cache – Tricky Interview Question

Integer a = 127;
Integer b = 127;
System.out.println(a == b);   // true  ← cached range -128 to 127

Integer c = 128;
Integer d = 128;
System.out.println(c == d);   // false ← outside cache, new objects
System.out.println(c.equals(d)); // true  ← compare value
🔑 Rule: Always use .equals() to compare Integer objects, never ==. The Integer cache only covers -128 to 127.

07 LinkedList – Doubly Linked List

Internal Structure

// Each element is a Node
private static class Node<E> {
    E       item;
    Node<E> next;   // pointer to next node
    Node<E> prev;   // pointer to previous node
}
// null ← [prev|A|next] ↔ [prev|B|next] ↔ [prev|C|next] → null
OperationComplexityWhy
get(index)O(n)Must traverse from head
add() at head/tailO(1)Pointer update only
add(index, e)O(n)Traverse + pointer update
remove() head/tailO(1)Pointer update only
 
LinkedList<String> ll = new LinkedList<>();

ll.add("B");
ll.addFirst("A");   // O(1) — add to head
ll.addLast("C");    // O(1) — add to tail

System.out.println(ll);           // [A, B, C]
System.out.println(ll.getFirst()); // A
System.out.println(ll.getLast());  // C

ll.removeFirst();  // O(1)
ll.removeLast();   // O(1)
💡 LinkedList also implements Deque — use it as a Stack (push/pop) or Queue (offer/poll).

08 Vector & Stack

Vector

Like ArrayList but synchronized (thread-safe). Every method is synchronized → slower.

Vector<Integer> v = new Vector<>();
v.add(10); v.add(20);
System.out.println(v);   // [10, 20]

// Growth: doubles capacity (ArrayList grows 1.5x)
// Default capacity = 10, grows to 20, 40...
⚠️ Vector is a legacy class. In modern code, use ArrayList + explicit synchronization, or CopyOnWriteArrayList instead.

Stack (LIFO)

Stack<Integer> stack = new Stack<>();

stack.push(10);   // add to top
stack.push(20);
stack.push(30);

System.out.println(stack.peek());  // 30 (view top, don't remove)
System.out.println(stack.pop());   // 30 (remove top)
System.out.println(stack.pop());   // 20
System.out.println(stack.isEmpty()); // false
💡 Prefer ArrayDeque over Stack for stack operations — faster and not synchronized by default.

09 final with List – Tricky Interview

🔑 Declaring a List as final prevents reassignment, but does NOT make it immutable. You can still add/remove elements.
final List<String> list = new ArrayList<>();

list.add("A");   // ✅ allowed — modifying contents
list.add("B");   // ✅ allowed
list.remove(0); // ✅ allowed

// list = new ArrayList<>(); // ❌ compile error — reassignment blocked

System.out.println(list);  // [B]

To Make a Truly Unmodifiable List

// Java 9+ — immutable list
List<String> immutable = List.of("A", "B", "C");
// immutable.add("D"); // ❌ UnsupportedOperationException

// Java 8 and below
List<String> locked = Collections.unmodifiableList(list);
// locked.add("X");  // ❌ UnsupportedOperationException

10 Custom ArrayList – No Duplicates Allowed

Classic interview question: "Create an ArrayList that doesn't allow duplicates."

import java.util.ArrayList;

public class CustomArrayList<E> extends ArrayList<E> {

    @Override
    public boolean add(E element) {
        if (this.contains(element)) {
            System.out.println("Duplicate rejected: " + element);
            return false;   // reject duplicate
        }
        return super.add(element);  // delegate to parent
    }

    @Override
    public void add(int index, E element) {
        if (!this.contains(element)) {
            super.add(index, element);
        }
    }
}

// Usage
public class Test {
    public static void main(String[] args) {
        CustomArrayList<Integer> list = new CustomArrayList<>();
        list.add(1);   // added
        list.add(2);   // added
        list.add(1);   // Duplicate rejected: 1
        list.add(3);   // added
        System.out.println(list);  // [1, 2, 3]
    }
}

12 HashSet – Deep Internal Working

HashSet internally uses a HashMap where your element is the key and a dummy constant (PRESENT) is the value.

// Inside HashSet source code:
private transient HashMap<E, Object> map;
private static final Object PRESENT = new Object();

public boolean add(E e) {
    return map.put(e, PRESENT) == null;
    // if put returns null → new key → added
    // if put returns PRESENT → duplicate → rejected
}

Duplicate Detection Flow

set.add("FB")
    ↓
Compute hashCode("FB") = 2236
    ↓
Calculate bucket index = hashCode & (capacity-1)
    ↓
Go to that bucket
    ↓
Is bucket empty?
    YES → store directly ✅
    NO  → equals() check on existing entries
              equals() true?  → DUPLICATE → reject ❌
              equals() false? → COLLISION → store in bucket chain ✅
HashSet<String> set = new HashSet<>();
set.add("Apple");
set.add("Banana");
set.add("Apple");    // duplicate — rejected silently
set.add(null);       // one null allowed

System.out.println(set.size());   // 3
System.out.println(set);          // order not guaranteed

13 equals() & hashCode() Contract

🔑 THE CONTRACT: If two objects are equal (equals() returns true), they MUST have the same hashCode(). Violating this breaks HashSet/HashMap.

Problem — Only equals() Overridden

class Student {
    int    id;
    String name;

    Student(int id, String name) { this.id=id; this.name=name; }

    @Override
    public boolean equals(Object o) {
        Student s = (Student) o;
        return this.id == s.id;  // same id = equal
    }
    // hashCode NOT overridden → uses Object's memory-address based hash
}

HashSet<Student> set = new HashSet<>();
set.add(new Student(1, "Alice"));
set.add(new Student(1, "Alice"));   // should be duplicate

System.out.println(set.size());   // 2 ❌ — duplicate NOT detected!
// Different hashCodes → different buckets → equals() never reached

Correct Implementation — Both Overridden

class Student {
    int    id;
    String name;

    Student(int id, String name) { this.id=id; this.name=name; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Student)) return false;
        Student s = (Student) o;
        return this.id == s.id && Objects.equals(this.name, s.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);   // same fields as equals()
    }
}

HashSet<Student> set = new HashSet<>();
set.add(new Student(1, "Alice"));
set.add(new Student(1, "Alice"));

System.out.println(set.size());   // 1 ✅ — duplicate correctly detected

14 LinkedHashSet

Maintains insertion order while still rejecting duplicates. Uses a HashMap + doubly linked list internally.

LinkedHashSet<Integer> lhs = new LinkedHashSet<>();
lhs.add(30); lhs.add(10); lhs.add(20); lhs.add(10);

System.out.println(lhs);   // [30, 10, 20] — insertion order, no duplicate
💡 Use LinkedHashSet when you need a unique collection and also want to preserve the order elements were added.

15 TreeSet – Sorted Set

TreeSet stores elements in sorted (natural) order using a Red-Black Tree internally.

TreeSet<Integer> ts = new TreeSet<>();
ts.add(50); ts.add(20); ts.add(80); ts.add(10); ts.add(20);

System.out.println(ts);           // [10, 20, 50, 80] — sorted, no dup
System.out.println(ts.first());   // 10
System.out.println(ts.last());    // 80
System.out.println(ts.headSet(50));  // [10, 20] — elements < 50
System.out.println(ts.tailSet(50));  // [50, 80] — elements >= 50
System.out.println(ts.floor(25));    // 20 — greatest element ≤ 25
System.out.println(ts.ceiling(25));  // 50 — smallest element ≥ 25

Custom Sort in TreeSet using Comparator

// Sort in descending order
TreeSet<Integer> desc = new TreeSet<>(Comparator.reverseOrder());
desc.add(30); desc.add(10); desc.add(50);
System.out.println(desc);   // [50, 30, 10]

// Sort Employee by name
TreeSet<Employee> empSet = new TreeSet<>(
    (Employee a, Employee b) -> a.name.compareTo(b.name)
);
⚠️ TreeSet does NOT allow null — throws NullPointerException. And elements must be Comparable or a Comparator must be provided.

16 Queue & PriorityQueue

Queue follows FIFO (First In, First Out). Elements are added at the tail and removed from the head.

MethodThrows ExceptionReturns null/false (safe)
Addadd(e)offer(e)
Removeremove()poll()
Peekelement()peek()

PriorityQueue – Min-Heap by Default

PriorityQueue<Integer> pq = new PriorityQueue<>();

pq.offer(50); pq.offer(10); pq.offer(30); pq.offer(20);

System.out.println(pq.peek());   // 10 — minimum always at head
System.out.println(pq.poll());   // 10 — removes minimum
System.out.println(pq.poll());   // 20
System.out.println(pq.poll());   // 30

// Max-Heap using reverseOrder
PriorityQueue<Integer> maxPQ = new PriorityQueue<>(Collections.reverseOrder());
maxPQ.offer(50); maxPQ.offer(10); maxPQ.offer(30);
System.out.println(maxPQ.peek());  // 50 — maximum at head

17 ArrayDeque – Double-Ended Queue

ArrayDeque supports adding/removing from both ends. Preferred over Stack and LinkedList for stack/queue operations — faster and no synchronization overhead.

ArrayDeque<String> deque = new ArrayDeque<>();

// Use as STACK (LIFO)
deque.push("First");
deque.push("Second");
deque.push("Third");
System.out.println(deque.pop());  // Third (LIFO)

// Use as QUEUE (FIFO)
deque.offerLast("A");
deque.offerLast("B");
System.out.println(deque.pollFirst());  // A (FIFO)

19 HashMap – Deep Internal Working

Internal Structure

// HashMap = Array of Buckets (Node linked list / Red-Black Tree)
transient Node<K,V>[] table;       // the bucket array
static final int DEFAULT_INITIAL_CAPACITY = 16;  // 2^4
static final float DEFAULT_LOAD_FACTOR   = 0.75f; // resize at 75% full

// Each Node stores:
static class Node<K,V> {
    final int hash;   K key;   V value;   Node<K,V> next;
}

put() Flow – Step by Step

map.put("Alice", 101)
      ↓
1. Compute hash = "Alice".hashCode()
      ↓
2. Bucket index = (n-1) & hash   (n = table length = 16)
      ↓
3. Is bucket empty?
      YES → create Node, store it ✅
      NO  → compare hash + equals()
              Duplicate key → UPDATE value ✅
              Collision      → CHAIN in LinkedList / Tree

Java 7 vs Java 8 Collision Handling

Java 7Java 8+
Collision storageLinkedList chainingLinkedList (small) → Red-Black Tree (large)
Threshold to treeifyN/ABucket size > 8
Average complexityO(1)O(1)
Worst caseO(n)O(log n)

Resizing / Rehashing

// HashMap resizes when: size > capacity * loadFactor
// Default: 16 * 0.75 = 12 → resize at 13th element
// New capacity = old capacity * 2 = 32
// All elements rehashed into new buckets — expensive O(n) operation

Complete HashMap Example

Map<String, Integer> map = new HashMap<>();

map.put("Alice", 101);
map.put("Bob",   102);
map.put("Alice", 999);   // updates existing key
map.put(null,    0);      // null key allowed (one)

System.out.println(map.get("Alice"));       // 999
System.out.println(map.getOrDefault("X", -1)); // -1

// Iterate over entries
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println(entry.getKey() + " → " + entry.getValue());
}

Mutable Key Problem

Employee e = new Employee(1, "Alice");
map.put(e, "Engineering");  // stored in bucket for hashCode=1

e.id = 999;   // mutate the key — hashCode changes!

System.out.println(map.get(e));   // null ❌ — wrong bucket
🔑 Always use immutable objects as HashMap keys. String is the ideal key — immutable + cached hashCode.

20 LinkedHashMap

HashMap + doubly linked list = insertion-order maintained. Also supports access-order for LRU cache.

LinkedHashMap<String, Integer> lhm = new LinkedHashMap<>();
lhm.put("Banana", 2);
lhm.put("Apple",  1);
lhm.put("Cherry", 3);
System.out.println(lhm);   // {Banana=2, Apple=1, Cherry=3} ← insertion order

// LRU Cache using access-order LinkedHashMap
LinkedHashMap<Integer, String> lruCache =
    new LinkedHashMap<>(16, 0.75f, true) {  // true = accessOrder
        @Override
        protected boolean removeEldestEntry(Map.Entry<Integer, String> eldest) {
            return size() > 3;   // max capacity = 3
        }
    };

21 TreeMap – Sorted Map

TreeMap stores keys in sorted (natural) order using a Red-Black Tree. All operations are O(log n).

TreeMap<String, Integer> tm = new TreeMap<>();
tm.put("Mango",  3);
tm.put("Apple",  1);
tm.put("Banana", 2);

System.out.println(tm);               // {Apple=1, Banana=2, Mango=3}
System.out.println(tm.firstKey());     // Apple
System.out.println(tm.lastKey());      // Mango
System.out.println(tm.headMap("Mango"));  // {Apple=1, Banana=2}
System.out.println(tm.tailMap("Banana")); // {Banana=2, Mango=3}
System.out.println(tm.floorKey("Cherry"));  // Banana
⚠️ TreeMap does NOT allow null keys. NullPointerException thrown at runtime.

23 Comparable vs Comparator

Comparable — Natural Sorting
• Defined inside the class
• Method: compareTo(T o)
• Single sorting sequence
• Modifies original class
• Package: java.lang
Comparator — Custom Sorting
• Defined in separate class
• Method: compare(T o1, T o2)
• Multiple sorting sequences
• Does NOT modify original class
• Package: java.util

Comparable Example – Sort by ID

class Employee implements Comparable<Employee> {
    int    id;
    String name;
    double salary;

    Employee(int id, String name, double salary) {
        this.id=id; this.name=name; this.salary=salary;
    }

    @Override
    public int compareTo(Employee other) {
        return this.id - other.id;   // sort by ID ascending
    }
}

List<Employee> list = Arrays.asList(
    new Employee(3, "Charlie", 50000),
    new Employee(1, "Alice",   70000),
    new Employee(2, "Bob",     60000)
);
Collections.sort(list);
// Output: [Alice(1), Bob(2), Charlie(3)] — sorted by ID

Comparator Example – Multiple Sort Strategies

// Sort by name
Comparator<Employee> byName = (Employee a, Employee b) ->
    a.name.compareTo(b.name);

// Sort by salary descending
Comparator<Employee> bySalaryDesc = (Employee a, Employee b) ->
    Double.compare(b.salary, a.salary);

// Chain multiple comparators
Comparator<Employee> byNameThenSalary =
    Comparator.comparing(e -> e.name)
              .thenComparingDouble(e -> e.salary);

list.sort(byName);
list.sort(bySalaryDesc);
list.sort(byNameThenSalary);

24 Iterator – fail-fast vs fail-safe

Iterator Methods

List<String> list = new ArrayList<>(Arrays.asList("A", "B", "C"));
Iterator<String> it = list.iterator();

while (it.hasNext()) {
    String s = it.next();
    if (s.equals("B")) {
        it.remove();   // ✅ safe removal during iteration
    }
}
System.out.println(list);   // [A, C]

Fail-Fast – ConcurrentModificationException

List<String> list = new ArrayList<>(Arrays.asList("A", "B", "C"));
Iterator<String> it = list.iterator();

while (it.hasNext()) {
    System.out.println(it.next());
    list.add("X");   // ❌ modifying list directly during iteration
}
// throws: ConcurrentModificationException

Fail-Safe – Works on a Clone

// CopyOnWriteArrayList — fail-safe
CopyOnWriteArrayList<String> cowList =
    new CopyOnWriteArrayList<>(Arrays.asList("A", "B", "C"));

for (String s : cowList) {
    cowList.add("X");   // ✅ no exception — iterator uses snapshot
    System.out.println(s);
}
// Output: A B C  (added X visible only in next iteration)
Fail-FastFail-Safe
Works onOriginal collectionCloned copy
Modification during iter❌ ConcurrentModificationException✅ No exception
MemoryLessMore (copy overhead)
ExamplesArrayList, HashMap, HashSetCopyOnWriteArrayList, ConcurrentHashMap
When to useSingle-threadedMulti-threaded

25 ConcurrentHashMap

Thread-safe HashMap with much better performance than Hashtable by locking only specific buckets instead of the whole map.

HashtableConcurrentHashMap
Lock scopeEntire map (one lock)Bucket level (Java 8: CAS)
Read operationsLocked✅ No lock
Null keys/values❌ No❌ No
PerformanceLow✅ High
IteratorFail-fastFail-safe (weakly consistent)
 
ConcurrentHashMap<String, Integer> chm = new ConcurrentHashMap<>();

// Thread 1
chm.put("A", 1);

// Thread 2 — concurrent read safe
chm.get("A");

// Atomic operations
chm.putIfAbsent("B", 2);      // insert if B not present
chm.computeIfAbsent("C", k -> 3);  // compute and insert
chm.merge("A", 10, Integer::sum);  // 1+10=11 atomically
✅ Real-world use: Use ConcurrentHashMap in Spring Boot services where multiple threads read/write shared state — e.g., in-memory caches, frequency counters.

26 CopyOnWriteArrayList

Thread-safe ArrayList where every write operation creates a fresh copy of the underlying array. Reads are fast; writes are expensive.

CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();
list.add("A"); list.add("B"); list.add("C");

// Safe iteration even with concurrent modification
for (String s : list) {
    System.out.print(s + " ");  // A B C
    list.add("X");             // ✅ no exception
}

28 Generics & Type Erasure

Why Generics?

// Without generics — raw type (Java 4 and below)
List raw = new ArrayList();
raw.add(10);
raw.add("Aryan");   // no compile error!
int x = (Integer) raw.get(1);  // ❌ ClassCastException at runtime

// With generics — type-safe
List<Integer> safe = new ArrayList<>();
safe.add(10);
// safe.add("Aryan"); // ❌ compile error — caught early!
int y = safe.get(0);   // ✅ no cast needed

Type Erasure

// At compile time: ArrayList<Integer>
// At runtime JVM sees: ArrayList (raw type)
// Generics are erased — only for compile-time safety

List<Integer> a = new ArrayList<>();
List<String>  b = new ArrayList<>();

System.out.println(a.getClass() == b.getClass());   // true!
// Both are just ArrayList at runtime — type info erased

Wildcards

// Upper bounded — accepts List<Integer>, List<Double> etc.
public double sumList(List<? extends Number> list) {
    return list.stream().mapToDouble(Number::doubleValue).sum();
}

// Lower bounded — accepts List<Number>, List<Object>
public void addNumbers(List<? super Integer> list) {
    list.add(10);
}

Q&A Interview Questions – Complete Set

Q1 What is the Collection Framework and why was it introduced?

Collection Framework is a unified architecture of interfaces, classes, and algorithms for storing and manipulating groups of objects dynamically. It was introduced because arrays have fixed size, no built-in methods, and cannot handle complex operations efficiently.

Q2 Does Map extend Collection? Why not?

No. Map stores key-value pairs — a fundamentally different structure from Collection which stores single elements. Collection interface methods like add(element) don't make sense for Map (put(key, value)). That's why Map has its own hierarchy.

Q3 Difference between ArrayList and LinkedList — when to use which?
ArrayListLinkedList
InternalDynamic arrayDoubly linked list
get(i)O(1) ✅O(n) ❌
add/remove middleO(n) — shiftingO(1) after traversal

Use ArrayList when frequent reads. Use LinkedList when frequent add/remove at head/tail.

Q4 Why can't we use primitive types in Collections?

Generics use type erasure — all type parameters become Object at runtime. Primitives (int, double) are NOT Objects. So we use wrapper classes (Integer, Double). The compiler handles the conversion automatically via AutoBoxing/Unboxing.

Q5 How does HashSet ensure no duplicates?

HashSet internally uses a HashMap. When you add(e), it calls map.put(e, PRESENT). HashMap checks:

  1. Same hashCode()?
  2. If yes → check equals()
  3. If both match → DUPLICATE → rejected

For custom objects you MUST override both hashCode() and equals(), otherwise duplicates sneak in.

Q6 What is the Integer cache? Why does 127 == 127 return true but 128 == 128 returns false?

Java caches Integer objects for values -128 to 127. In this range, Integer.valueOf() returns the cached object. Outside this range, a new object is created each time. So == compares references — same cached object = true, different heap objects = false. Always use .equals().

Integer a = 127; Integer b = 127;
System.out.println(a == b);   // true  (cached)
Integer c = 128; Integer d = 128;
System.out.println(c == d);   // false (new objects)
Q7 What happens internally when HashMap grows? What is load factor?

Load factor = threshold to trigger resizing = 0.75 by default. When size > capacity × loadFactor (e.g., 16 × 0.75 = 12), the map doubles capacity to 32 and rehashes all existing entries into new buckets. This is an O(n) operation.

Q10 What is fail-fast and fail-safe iterator?

Fail-fast: Iterator throws ConcurrentModificationException if the collection is structurally modified while iterating (ArrayList, HashMap).

Fail-safe: Iterator works on a snapshot/clone — no exception (ConcurrentHashMap, CopyOnWriteArrayList). But may not reflect recent changes.

Q11 How to safely remove elements while iterating?

// ✅ Option 2: removeIf (Java 8)
list.removeIf(x -> x % 2 == 0);

// ✅ Option 3: Use CopyOnWriteArrayList
// ❌ WRONG: list.remove() inside for-each → ConcurrentModificationException
Q12 ConcurrentHashMap vs Hashtable — what's the difference?

Hashtable locks the entire map for every operation — only one thread can read or write at a time. ConcurrentHashMap uses bucket-level locking (Java 7: segment locks; Java 8: CAS + synchronized per bucket). Reads in ConcurrentHashMap require no lock at all. Much better throughput in multi-threaded environments.

Q14 Can you add to a final List? What does final mean for collections?

Yes, you can add elements. final on a reference variable prevents reassignment of the reference, but does NOT make the collection immutable. The contents can still be modified. For a truly immutable list, use Collections.unmodifiableList() or List.of() (Java 9+).

Q15 How to implement an LRU cache using Java Collections?
class LRUCache<K, V> extends LinkedHashMap<K, V> {
    private final int capacity;

    LRUCache(int capacity) {
        super(capacity, 0.75f, true);  // accessOrder = true
        this.capacity = capacity;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K,V> eldest) {
        return size() > capacity;  // evict LRU when full
    }
}
LRUCache<Integer,String> cache = new LRUCache<>(3);
cache.put(1,"A"); cache.put(2,"B"); cache.put(3,"C");
cache.get(1);     // access 1 → moves to end
cache.put(4,"D"); // evicts LRU: key 2
System.out.println(cache);  // {3=C, 1=A, 4=D}
Q16 Write a custom ArrayList that disallows duplicates.

Extend ArrayList and override the add() method to check contains() before delegating to super.add(). See Section 10 for full code.

Q17 What is the difference between poll() and remove() in Queue?

Both remove the head element. But remove() throws NoSuchElementException if the queue is empty, while poll() returns null safely. Same pattern: add() vs offer(), element() vs peek().

Q18 What is the internal structure of TreeMap/TreeSet?

Both use a Red-Black Tree — a self-balancing binary search tree. Every operation (put, get, remove) is O(log n). Elements must be Comparable or a Comparator must be provided. Does not allow null keys.

Q19 What is type erasure in Java Generics?

At compile time, the compiler enforces generic type constraints. But at runtime, all type parameters are erased and replaced with Object (or the bound type). So ArrayList<Integer> and ArrayList<String> are the same class at runtime. This is why generics don't work with primitives and why you can't do new T().

Q26 What is ArrayDeque and why prefer it over Stack?

ArrayDeque is a resizable double-ended queue. Preferred over Stack because: (1) Stack extends Vector — synchronized overhead. (2) ArrayDeque is not synchronized — faster in single-threaded use. (3) ArrayDeque is a Deque — can be used as both stack (LIFO) and queue (FIFO).

// Avoids multiple resize + array copy operations

// Trim to actual size
((ArrayList<String>) list).trimToSize();  // release unused capacity

// Ensure capacity
((ArrayList<String>) list).ensureCapacity(2000);

Q29 What is the difference between HashMap's put() and putIfAbsent()?
Map<String,Integer> map = new HashMap<>();
map.put("A", 1);

// put() — always inserts/updates
map.put("A", 99);                // value updated to 99

// putIfAbsent() — only if key absent
map.putIfAbsent("A", 999);          // value stays 99 — key exists
map.putIfAbsent("B", 2);            // B=2 added

// computeIfAbsent() — compute + insert if absent
map.computeIfAbsent("C", k -> k.length());  // C=1
Q30 How to make a thread-safe version of ArrayList or HashMap without using Concurrent classes?
// Thread-safe List
List<String> syncList = Collections.synchronizedList(new ArrayList<>());

// Thread-safe Map
Map<String,Integer> syncMap = Collections.synchronizedMap(new HashMap<>());

// WARNING: Must synchronize manually during iteration!
synchronized(syncList) {
    for (String s : syncList) {
        System.out.println(s);
    }
}
