▌ Part 1 — Marker Interfaces

01 What is a Marker Interface?

A Marker Interface is an interface that has no methods and no fields. It is used purely to provide metadata / a signal to the JVM or framework about the capability of a class.

// This is all a marker interface contains — nothing!
public interface Serializable {
    // no methods
    // no fields
    // just a tag
}
📌 One-liner: A marker interface is an empty interface that acts as a label or tag for a class, telling the JVM or runtime what that class is capable of.

How JVM Uses It

Class implements MarkerInterface
         ↓
JVM / Runtime checks with instanceof
         ↓
Enables a special behaviour
         ↓
(serialization / cloning / remote access...)

Internal Check Example

// Internally JVM does something like this:
if (obj instanceof Serializable) {
    // allow serialization
} else {
    throw new NotSerializableException();
}

02 Why Marker Interfaces Exist

Before Java 5 (before annotations were introduced), there was no way to attach metadata to a class without writing actual code. Marker interfaces were the only mechanism to signal intent to the JVM.

ProblemMarker Interface Solution
How to tell JVM this class can be serialized?Implement Serializable
How to tell JVM this object can be cloned?Implement Cloneable
How to tell RMI this is a remote object?Implement Remote
How to tell JVM ArrayList supports fast random access?Implement RandomAccess
💡 Marker interfaces work via instanceof checks at runtime. They have zero performance cost — they are just a type check.

Compile-time Type Safety

// Marker interfaces enforce type safety at compile time
public static void serialize(Serializable obj) {
    // only Serializable objects can be passed here
    // compiler rejects non-Serializable objects
}

serialize(new Employee());   // ✅ if Employee implements Serializable
serialize(new Car());        // ❌ compile error if Car doesn't

04 Cloneable Marker Interface

Without Cloneable, calling clone() throws CloneNotSupportedException at runtime.

Without Cloneable (breaks at runtime)

class Employee {   // NOT Cloneable
    int id = 101;
}

Employee e1 = new Employee();
Employee e2 = (Employee) e1.clone();
// ❌ throws CloneNotSupportedException

With Cloneable (works correctly)

class Employee implements Cloneable {
    int    id   = 101;
    String name = "Aryan";

    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone();   // shallow copy
    }
}

Employee e1 = new Employee();
Employee e2 = (Employee) e1.clone();

System.out.println(e2.id);    // 101
System.out.println(e1 == e2); // false → different objects
⚠️ clone() creates a shallow copy by default. For deep copy, override clone() and manually copy mutable fields.

05 Remote Marker Interface (RMI)

The Remote interface marks objects that can be called from a different JVM over a network — this is called RMI (Remote Method Invocation).

import java.rmi.*;

// Step 1: Define remote interface extending Remote
public interface HelloService extends Remote {
    String sayHello() throws RemoteException;
}

// Step 2: Implement it — object is now remotely accessible
public class HelloServiceImpl extends UnicastRemoteObject
        implements HelloService {

    public String sayHello() throws RemoteException {
        return "Hello from remote JVM!";
    }
}
💡 In microservices today, REST/gRPC replaced RMI for remote calls. But Remote marker is still asked in interviews.

▌ Part 2 — Serialization

07 What is Serialization?

Serialization = converting a Java object into a byte stream so it can be stored, transferred, or reconstructed later.

Deserialization = converting that byte stream back into the original object.

Employee e = new Employee(101, "Aryan");
// Object currently lives in RAM
// If app stops → object destroyed
// Solution: serialize → save to file/DB/network

When Do We Need Serialization?

  • Saving object to a file (persistence)
  • Sending object over a network
  • Storing object in HTTP session
  • Transferring between JVMs
  • Caching (Redis, Memcached)
  • Deep copy of object

09 Serializable Interface

Serializable is a marker interface in java.io. It signals to the JVM that objects of this class are allowed to be serialized.

import java.io.Serializable;

class Employee implements Serializable {
    int    id;
    String name;
}
// JVM now allows: Employee object → byte stream ✅

Without Serializable → Runtime Exception

java.io.NotSerializableException: Employee

at java.io.ObjectOutputStream.writeObject0(...)
at java.io.ObjectOutputStream.writeObject(...)
🔑 NotSerializableException is a runtime exception — the compiler will NOT catch it. The check happens inside writeObject() at execution time.

10 Complete Serialization Example

import java.io.*;

class Employee implements Serializable {

    private static final long serialVersionUID = 1L;

    int    id;
    String name;

    Employee(int id, String name) {
        this.id   = id;
        this.name = name;
    }
}

public class SerializeDemo {

    public static void main(String[] args) throws Exception {

        Employee e = new Employee(101, "Aryan");

        // Step 1: Open output stream to file
        FileOutputStream   fos = new FileOutputStream("emp.ser");

        // Step 2: Wrap with ObjectOutputStream
        ObjectOutputStream oos = new ObjectOutputStream(fos);

        // Step 3: Serialize
        oos.writeObject(e);

        oos.close();
        fos.close();

        System.out.println("✅ Object Serialized → emp.ser");
    }
}
💡 Use .ser extension by convention — it signals the file contains serialized Java objects.

11 Complete Deserialization Example

import java.io.*;

public class DeserializeDemo {

    public static void main(String[] args) throws Exception {

        // Step 1: Open input stream from file
        FileInputStream   fis = new FileInputStream("emp.ser");

        // Step 2: Wrap with ObjectInputStream
        ObjectInputStream ois = new ObjectInputStream(fis);

        // Step 3: Deserialize and cast
        Employee e = (Employee) ois.readObject();

        ois.close();
        fis.close();

        System.out.println("id   = " + e.id);    // 101
        System.out.println("name = " + e.name);  // Aryan
    }
}
id   = 101
name = Aryan

12 transient Keyword

transient tells the JVM: "Do NOT include this field in the byte stream."

import java.io.*;

class Employee implements Serializable {

    private static final long serialVersionUID = 1L;

    int    id       = 101;
    String name     = "Aryan";
    transient String password = "secret123";  // skipped!
    transient int    otp      = 9876;          // skipped!
}

// After deserialization:
// e.id       → 101
// e.name     → "Aryan"
// e.password → null    ← transient default
// e.otp      → 0       ← transient int default

transient Default Values After Deserialization

TypeDefault After Deserialization
Object (String, etc.)null
int, long, double0
booleanfalse
char'\u0000'

Real-World Use of transient

  • Passwords / secret keys
  • OTPs / session tokens
  • DB connections (not serializable anyway)
  • Computed/cache fields (can be recalculated)
  • Logger instances
✅ Rule: Any field that is sensitive, temporary, or non-serializable should be marked transient.

13 static Variables and Serialization

🔑 Static variables are NEVER serialized. They belong to the class, not to any object instance. Serialization captures object state, not class-level data.
class Employee implements Serializable {

    static  String company = "TCS";  // NOT serialized
    int            id      = 101;   // serialized ✅
    String         name    = "Aryan"; // serialized ✅
}

// After deserialization:
// e.company → loaded from class definition (current JVM value)
// e.id      → 101 (restored from bytes)
// e.name    → "Aryan" (restored from bytes)
Field TypeSerialized?Why
Instance field✅ YesPart of object state
transient field❌ NoExplicitly excluded
static field❌ NoBelongs to class, not object
static transient❌ NoBoth reasons apply

14 serialVersionUID

A unique version ID that the JVM uses to verify compatibility between a serialized byte stream and the current class definition during deserialization.

class Employee implements Serializable {

    private static final long serialVersionUID = 1L;

    int    id;
    String name;
}

What Happens Without It

Step 1: Serialize Employee (JVM auto-generates serialVersionUID = X)
            ↓
Step 2: Add new field "salary" to Employee class
            ↓
Step 3: Deserialize — JVM computes new serialVersionUID = Y
            ↓
        X ≠ Y → InvalidClassException ❌

What Happens With It

Step 1: Serialize Employee  (serialVersionUID = 1L)
            ↓
Step 2: Add new field "salary"  (serialVersionUID still = 1L)
            ↓
Step 3: Deserialize — serialVersionUID = 1L matches ✅
            ↓
        New field "salary" → default value (0 or null)
⚠️ Always declare serialVersionUID explicitly in Serializable classes. Without it, any class change will break deserialization of old data.
// Version 1 — Original class
class Employee implements Serializable {
    private static final long serialVersionUID = 1L;
    int id; String name;
}

// Version 2 — New field added, same UID → compatible ✅
class Employee implements Serializable {
    private static final long serialVersionUID = 1L;
    int id; String name; double salary;  // salary = 0.0 on deserialize
}

15 Constructor Behavior During Deserialization

⭐ VERY FAMOUS INTERVIEW QUESTION — Is the constructor called during deserialization?
🔑 Answer: NO. The constructor is NOT called during deserialization. The object is reconstructed directly from the byte stream, bypassing the constructor entirely.
import java.io.*;

class Employee implements Serializable {

    private static final long serialVersionUID = 1L;
    int id; String name;

    Employee(int id, String name) {
        System.out.println("Constructor Called!");
        this.id = id; this.name = name;
    }
}

public class Test {
    public static void main(String[] args) throws Exception {

        // SERIALIZE
        Employee e = new Employee(101, "Aryan");
        // Output: Constructor Called!

        ObjectOutputStream oos = new ObjectOutputStream(new FileOutputStream("emp.ser"));
        oos.writeObject(e);
        oos.close();

        // DESERIALIZE
        ObjectInputStream ois = new ObjectInputStream(new FileInputStream("emp.ser"));
        Employee e2 = (Employee) ois.readObject();
        ois.close();
        // Output: (nothing — constructor NOT called)

        System.out.println(e2.id + " " + e2.name); // 101 Aryan
    }
}
Constructor Called!
101 Aryan

Notice: "Constructor Called!" prints only once — during new Employee(). Never during readObject().

16 Serialization with Inheritance

Case 1: Parent NOT Serializable, Child IS Serializable

class Animal {               // NOT Serializable
    String type = "Mammal";

    Animal() {
        System.out.println("Animal constructor called!");
    }
}

class Dog extends Animal implements Serializable {
    private static final long serialVersionUID = 1L;
    String name = "Bruno";
}

// On deserialization:
// → Animal constructor IS called (parent state not in bytes)
// → Dog's fields restored from byte stream
// Output: "Animal constructor called!"
⚠️ If parent is NOT Serializable, its no-arg constructor must exist and will be called during deserialization. If missing → InvalidClassException.

Case 2: Parent IS Serializable, Child IS Serializable

class Animal implements Serializable {   // Parent Serializable
    String type = "Mammal";
}

class Dog extends Animal {               // Child inherits Serializable
    private static final long serialVersionUID = 1L;
    String name = "Bruno";
}

// Both parent and child state serialized ✅
// Constructor NOT called during deserialization
ScenarioParent Constructor Called?Child State Restored?
Parent ✅ Serializable + Child ✅❌ No✅ Yes (fully)
Parent ❌ NOT Serializable + Child ✅✅ Yes✅ Yes (child only)

17 Can Private Fields Be Serialized?

✅ YES — private fields ARE serialized. Serialization works at JVM level and bypasses Java access modifiers completely.
class BankAccount implements Serializable {

    private static final long serialVersionUID = 1L;

    private int    accountNo = 12345;
    private double balance   = 50000.0;

    // After deserialization:
    // accountNo → 12345 ✅  (private, but still serialized)
    // balance   → 50000.0 ✅
}

This is why sensitive private fields like passwords should be marked transient — just being private does NOT protect them from serialization.

18 Collections Serialization

Collections like ArrayList, HashMap, HashSet already implement Serializable. They can be serialized only if all contained objects are also Serializable.

import java.io.*;
import java.util.*;

class Employee implements Serializable {
    private static final long serialVersionUID = 1L;
    int id; String name;
    Employee(int id, String name) { this.id=id; this.name=name; }
}

public class CollectionSerialize {

    public static void main(String[] args) throws Exception {

        List<Employee> list = new ArrayList<>();
        list.add(new Employee(1, "Alice"));
        list.add(new Employee(2, "Bob"));

        // Serialize list
        ObjectOutputStream oos = new ObjectOutputStream(
                new FileOutputStream("list.ser"));
        oos.writeObject(list);
        oos.close();

        // Deserialize list
        ObjectInputStream ois = new ObjectInputStream(
                new FileInputStream("list.ser"));

        List<Employee> restored = (List<Employee>) ois.readObject();
        ois.close();

        restored.forEach(e ->
            System.out.println(e.id + " " + e.name));
        // 1 Alice
        // 2 Bob
    }
}
⚠️ If even one element inside the collection is NOT Serializable → NotSerializableException for the whole collection.

Deep Copy Using Serialization

public static <T extends Serializable> T deepCopy(T obj) throws Exception {

    ByteArrayOutputStream bos = new ByteArrayOutputStream();
    ObjectOutputStream    oos = new ObjectOutputStream(bos);
    oos.writeObject(obj);

    ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
    ObjectInputStream   ois = new ObjectInputStream(bis);

    return (T) ois.readObject();  // completely independent copy
}

// Serialize
oos.writeObject(employee);

Q5 What happens if a class does NOT implement Serializable?

A runtime exception is thrown when you try to serialize it:

java.io.NotSerializableException: ClassName

It is a runtime exception — the compiler does NOT catch it.

Q6 ⭐ Is the constructor called during deserialization?

NO. The object is reconstructed directly from the byte stream. The constructor is completely bypassed. This is also why final fields that depend on constructor logic can be problematic with serialization.

Exception: If the parent class is NOT Serializable, its no-arg constructor is called during deserialization.

Q7 What is the transient keyword? When do you use it?

transient tells JVM to skip this field during serialization. After deserialization, the field gets its default value (null, 0, false).

transient String password;  // null after deserialization
transient int    otp;        // 0   after deserialization

Use it for: passwords, secret keys, DB connections, logger instances, computed cache fields.

Q8 Are static variables serialized?

NO. Static variables belong to the class, not to any object. Serialization only captures object state. After deserialization, static fields take their current value from the class definition in the JVM.

Q9 What is serialVersionUID? Why is it important?

A private static final long that uniquely identifies a class version. JVM checks it during deserialization to ensure the serialized data and current class are compatible.

private static final long serialVersionUID = 1L;

If the IDs don't match → InvalidClassException. Always declare it explicitly to control version compatibility.

Q10 Can private fields be serialized?

YES. Serialization works at JVM level and completely ignores access modifiers. private fields are serialized just like public ones. To protect sensitive private fields, mark them transient.

Q11 What happens when parent is NOT Serializable but child IS?

During deserialization, the parent's no-arg constructor is called (parent state is not in the byte stream). The child's fields are restored from bytes. If the parent has no no-arg constructor → InvalidClassException.

class Animal {
    Animal() { System.out.println("Animal constructor!"); }
}
class Dog extends Animal implements Serializable { ... }
// deserializing Dog → prints "Animal constructor!"
Q12 Can you serialize a collection like ArrayList?

Yes — ArrayList already implements Serializable. However, every element inside must also be Serializable. If even one element is not, you get NotSerializableException.

Q13 Which exception occurs on serialVersionUID mismatch?
java.io.InvalidClassException: Employee; local class incompatible:
stream classdesc serialVersionUID = 1, local class serialVersionUID = 2
Q14 What is the advantage of Marker Interface over Annotation?

Marker interfaces provide compile-time type safety through generics — something annotations cannot do:

// With marker interface — compiler enforces this:
public <T extends Serializable> void save(T obj) { ... }

// With annotation — only a runtime check is possible

Also, marker interfaces are inherited by subclasses automatically; annotations are not.

Q16 Where did you use Serialization in your project?

In a Spring Boot project, Serialization is used in: HTTP sessions (session replication), Redis caching (entities stored as bytes), and JMS messaging (objects sent as messages). All @Entity or cached objects should implement Serializable for safe session replication.

Q17 Why should you always declare serialVersionUID explicitly?

Without it, JVM auto-generates a UID based on class structure. Any change (adding/removing a field or method) changes the auto-generated UID, making old serialized data unreadable. Declaring it explicitly gives you control over backward compatibility.

Q18 How would you do a deep copy of an object using Serialization?
public static <T extends Serializable> T deepCopy(T obj) throws Exception {
    ByteArrayOutputStream bos = new ByteArrayOutputStream();
    new ObjectOutputStream(bos).writeObject(obj);
    return (T) new ObjectInputStream(
            new ByteArrayInputStream(bos.toByteArray())).readObject();
}

Serialize to bytes → deserialize → completely independent copy. No reference sharing.

Q19 Why is String Serializable?

String implements Serializable because strings are widely used in objects that need to be serialized (sessions, cache, network transfer). Since String is immutable, serialization is also safe — no side effects from shared references.

Q20 What is Externalizable? How is it different from Serializable?

    public void writeExternal(ObjectOutput out) throws IOException {
        out.writeInt(id);           // you choose what to save
