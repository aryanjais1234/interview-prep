01 Process vs Thread

A Process is an independent program running in memory while Thread is a lightweight unit of execution inside a process. 

Chrome Browser Process
   ├── UI Thread
   ├── Rendering Thread
   ├── Network Thread
   └── Background Worker Thread
Process Thread
Heavyweight Lightweight
Separate memory Shared memory
Slow context switch Fast context switch
Independent Dependent on process
Interview Point: Java applications run as a single process but can contain multiple threads.

02 How JVM Handles Threads Internally

When Java program starts: 

JVM Process Starts
    ↓
Main Thread Created
    ↓
Main Method Executes
    ↓
JVM Also Creates:
   • GC Thread
   • Compiler Thread
   • Signal Dispatcher
   • Finalizer Thread

Java threads are mapped to native OS threads.

Important: JDK provides APIs but actual scheduling is done by Operating System scheduler.

Context Switching

CPU switches between threads very fast creating illusion of parallelism.

04 Creating Threads

1. Extending Thread Class

class MyThread extends Thread {

    public void run() {
        System.out.println(
            Thread.currentThread().getName()
        );
    }
}

public class Test {
    public static void main(String[] args) {

        MyThread t1 = new MyThread();
        t1.start();
    }
}

2. Implementing Runnable

class MyTask implements Runnable {

    public void run() {
        System.out.println("Task running");
    }
}

Thread t = new Thread(new MyTask());
t.start();
Interview Point: Runnable is preferred because Java supports single inheritance.

3. Lambda Thread

Thread t = new Thread(() -> {
    System.out.println("Lambda Thread");
});

t.start();

06 Synchronization

Synchronization is used to avoid data inconsistency when multiple threads access shared resources.

Without Synchronization

class Counter {

    int count = 0;

    public void increment() {
        count++;
    }
}
count++ is NOT atomic. Internally: 1. Read 2. Increment 3. Write

With Synchronization

class Counter {

    int count = 0;

    public synchronized void increment() {
        count++;
    }
}

Synchronized Block

synchronized(this) {
    count++;
}

07 Race Condition

Race Condition occurs when multiple threads modify shared data simultaneously leading to inconsistent results. 

Expected Count = 2000
Actual Count = 1734
Most asked interview topic. Race condition is solved using synchronization/locks/atomic classes.

08 Deadlock

Deadlock occurs when two or more threads wait forever for each other’s locks. 

Thread-1:
Lock A → waiting for Lock B

Thread-2:
Lock B → waiting for Lock A

Deadlock Example

synchronized(lock1) {

    synchronized(lock2) {

    }
}
Prevention: • Lock ordering • Timeout • Avoid nested locks

09 Inter Thread Communication

Method Purpose
wait() Release lock and wait
notify() Wake one thread
notifyAll() Wake all threads 
synchronized(obj) {

    obj.wait();

    obj.notify();
}
wait(), notify() and notifyAll() belong to Object class not Thread class.

10 volatile Keyword

volatile ensures visibility of variable changes across threads. 

class Shared {

    volatile boolean flag = true;
}
volatile solves visibility issue but NOT atomicity issue.

11 Executor Framework

Introduced to manage threads efficiently instead of manually creating threads. 

ExecutorService service =
    Executors.newFixedThreadPool(3);

service.submit(() -> {
    System.out.println(
        Thread.currentThread().getName()
    );
});

service.shutdown();
ExecutorService internally manages thread pool and task queue.

15 Most Asked Interview Questions

Q1 Difference between process and thread?
Process has separate memory space while threads share same process memory.
Q2 Difference between start() and run()?
start() creates new thread while run() behaves like normal method call.
Q3 Why Runnable preferred over Thread?
Because Java supports single inheritance and Runnable provides better separation of task and thread.
Q4 What is synchronization?
Mechanism to control access to shared resources by multiple threads.
Q5 What is race condition?
When multiple threads update shared data simultaneously causing inconsistent results.
Q6 What is deadlock?
Situation where threads wait forever for each other's locks.
Q7 Difference between wait() and sleep()?
wait() releases lock while sleep() does not release lock.
Q8 Why wait(), notify() are inside Object class?
Because locks belong to objects and not threads.
Q9 What is volatile keyword?
volatile guarantees visibility of latest variable value across threads.
Q10 Difference between synchronized and volatile?
synchronized provides atomicity + visibility while volatile provides only visibility.
Q11 What is Thread Pool?
Collection of reusable worker threads managed by Executor Framework.
Q12 Difference between Runnable and Callable?
Callable returns value and throws checked exceptions while Runnable does not.
Q13 What is Future?
Represents result of asynchronous computation.
Q14 What is starvation?
When low priority thread never gets CPU time.
Q15 What is livelock?
Threads keep responding to each other but make no progress.

🔥 Interview Tips

  • Synchronization, Deadlock and volatile are extremely important.
  • wait vs sleep is one of the most asked questions.
  • ExecutorService is heavily asked in Spring Boot interviews.
  • Understand JVM + OS interaction properly.
  • ConcurrentHashMap internal working is important.
