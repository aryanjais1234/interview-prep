▌ Part 1 — Functional Interfaces

01 What is a Functional Interface?

A Functional Interface is an interface with exactly ONE abstract method. It can have any number of default/static methods. Annotated with @FunctionalInterface (optional but recommended).

@FunctionalInterface
public interface Runnable {
    void run();   // exactly ONE abstract method
}

// @FunctionalInterface enforces the rule at compile time:
@FunctionalInterface
interface MyFunc {
    void doSomething();
    // void another();  // ❌ compile error — 2 abstract methods
    default void helper() {}   // ✅ default methods allowed
    static void  util() {}      // ✅ static methods allowed
}

Built-in Functional Interfaces in java.util.function

Predicate<T>
T → boolean
Tests a condition. Used in filter(), anyMatch(), removeIf().
Function<T, R>
T → R
Transforms input to output. Used in map(), computeIfAbsent().
Consumer<T>
T → void
Consumes input, returns nothing. Used in forEach(), peek().
Supplier<T>
() → T
Supplies a value with no input. Used in Optional.orElseGet().

02 Predicate<T>

Signature: boolean test(T t) — evaluates a condition on input and returns true/false.

import java.util.function.Predicate;

Predicate<Integer> isEven  = n -> n % 2 == 0;
Predicate<Integer> isPos   = n -> n > 0;
Predicate<String>  isLong  = s -> s.length() > 5;

System.out.println(isEven.test(4));           // true
System.out.println(isEven.test(3));           // false

// Compose predicates
Predicate<Integer> isEvenAndPos = isEven.and(isPos);
Predicate<Integer> isEvenOrPos  = isEven.or(isPos);
Predicate<Integer> isOdd         = isEven.negate();

System.out.println(isEvenAndPos.test(4));    // true
System.out.println(isEvenAndPos.test(-4));   // false (not positive)
System.out.println(isOdd.test(3));           // true

// Used in Stream.filter()
List<Integer> evens = List.of(1,2,3,4,5,6).stream()
    .filter(isEven)
    .collect(Collectors.toList());   // [2, 4, 6]
MethodDescription
test(T t)Evaluate condition → boolean
and(Predicate p)Logical AND of two predicates
or(Predicate p)Logical OR of two predicates
negate()Logical NOT of the predicate
Predicate.not(p)Static NOT (Java 11+)

03 Function<T, R>

Signature: R apply(T t) — takes one input, produces one output of possibly different type.

import java.util.function.Function;

Function<String, Integer> strLen    = s -> s.length();
Function<Integer, Integer> square  = n -> n * n;
Function<String, String>  toUpper  = String::toUpperCase;

System.out.println(strLen.apply("Hello"));   // 5
System.out.println(square.apply(4));          // 16

// andThen — chain: apply f1 first, then f2
Function<String, Integer> lenThenSquare =
    strLen.andThen(square);
System.out.println(lenThenSquare.apply("Hello")); // 25 (len=5, 5*5=25)

// compose — chain: apply f2 first, then this
Function<String, Integer> squareThenLen =
    strLen.compose(toUpper);// toUpper applied first
// toUpper("hello") = "HELLO", then len = 5

// identity — returns input as-is
Function<String, String> id = Function.identity();

UnaryOperator — special case of Function<T,T>

import java.util.function.UnaryOperator;

UnaryOperator<String> trim       = String::trim;
UnaryOperator<Integer> increment = n -> n + 1;

System.out.println(trim.apply("  hello  "));  // "hello"
System.out.println(increment.apply(5));       // 6

List<String> names = new ArrayList<>(List.of("alice","bob"));
names.replaceAll(String::toUpperCase);   // [ALICE, BOB]

04 Consumer<T>

Signature: void accept(T t) — consumes input, produces no output. Used for side effects.

import java.util.function.Consumer;

Consumer<String>  print    = s -> System.out.println(s);
Consumer<String>  saveDB   = s -> System.out.println("Saving: " + s);
Consumer<Integer> logNum  = n -> System.out.println("Log: " + n);

print.accept("Hello");   // Hello

// andThen — chain consumers
Consumer<String> printAndSave = print.andThen(saveDB);
printAndSave.accept("Alice");
// Hello  (print)
// Saving: Alice  (saveDB)

// Used in forEach()
List.of("A","B","C").forEach(print);   // A B C
List.of("A","B").forEach(s -> {
    // multi-statement consumer
    String upper = s.toUpperCase();
    System.out.println(upper);
});

05 Supplier<T>

Signature: T get() — takes NO input, returns a value. Lazy evaluation / factory pattern.

import java.util.function.Supplier;

Supplier<String>    greet    = () -> "Hello, World!";
Supplier<Double>    random   = Math::random;
Supplier<List<String>> listFactory = ArrayList::new;

System.out.println(greet.get());       // Hello, World!
System.out.println(random.get());      // 0.7234... (random)

// Used in Optional.orElseGet() — lazy evaluation
Optional<String> opt = Optional.empty();
String result = opt.orElseGet(() -> "Default Value");
System.out.println(result);   // Default Value

// Key: orElse() ALWAYS evaluates, orElseGet() LAZY
String r1 = opt.orElse(expensiveCall());      // always called
String r2 = opt.orElseGet(() -> expensiveCall()); // called only if empty

06 Bi-variants & Operators

import java.util.function.*;

// BiPredicate<T,U> — test with 2 inputs
BiPredicate<String, Integer> longerThan =
    (s, n) -> s.length() > n;
System.out.println(longerThan.test("Hello", 3));  // true

// BiFunction<T,U,R> — 2 inputs, 1 output
BiFunction<String, String, String> concat =
    (a, b) -> a + " " + b;
System.out.println(concat.apply("Hello", "World"));  // Hello World

// BiConsumer<T,U> — 2 inputs, no output
BiConsumer<String, Integer> display =
    (name, age) -> System.out.println(name + " is " + age);
display.accept("Alice", 30);   // Alice is 30

// BinaryOperator<T> — 2 inputs of same type, same output
BinaryOperator<Integer> sum = (a, b) -> a + b;
BinaryOperator<Integer> max = Integer::max;
System.out.println(sum.apply(3, 5));   // 8
System.out.println(max.apply(3, 5));   // 5
InterfaceSignatureAbstract Method
Predicate<T>T → booleantest(T)
Function<T,R>T → Rapply(T)
Consumer<T>T → voidaccept(T)
Supplier<T>() → Tget()
UnaryOperator<T>T → Tapply(T)
BinaryOperator<T>(T,T) → Tapply(T,T)
BiPredicate<T,U>(T,U) → booleantest(T,U)
BiFunction<T,U,R>(T,U) → Rapply(T,U)
BiConsumer<T,U>(T,U) → voidaccept(T,U)

07 Custom Functional Interface

// Custom functional interface — real-world use case
@FunctionalInterface
interface TriFunction<A, B, C, R> {
    R apply(A a, B b, C c);
}

@FunctionalInterface
interface ThrowingFunction<T, R> {
    R apply(T t) throws Exception;  // allows checked exceptions
}

@FunctionalInterface
interface Validator<T> {
    boolean validate(T value);
    default Validator<T> and(Validator<T> other) {
        return t -> this.validate(t) && other.validate(t);
    }
}

// Usage
Validator<String> notEmpty   = s -> !s.isEmpty();
Validator<String> maxLen10   = s -> s.length() <= 10;
Validator<String> emailCheck = s -> s.contains("@");

Validator<String> emailValidator = notEmpty.and(maxLen10).and(emailCheck);
System.out.println(emailValidator.validate("a@b.com"));   // true
System.out.println(emailValidator.validate("invalid"));    // false

▌ Part 2 — Lambda & Method References

08 Lambda Expressions

A lambda is a concise way to implement a functional interface without writing a full anonymous class.

// Syntax: (parameters) -> expression  OR  (parameters) -> { body; }

// Anonymous class — old way
Runnable r1 = new Runnable() {
    public void run() { System.out.println("Running"); }
};

// Lambda — concise
Runnable r2 = () -> System.out.println("Running");

// Various lambda forms
Comparator<Integer> c1 = (a, b) -> a - b;           // no types (inferred)
Comparator<Integer> c2 = (Integer a, Integer b) -> a - b; // explicit types
Predicate<String>   p1 = s -> s.isEmpty();           // single param, no parens
Supplier<String>    s1 = () -> "hello";               // no params
Function<Integer,Integer> f = n -> {                   // block body
    int squared = n * n;
    return squared;
};

Lambda vs Anonymous Class

LambdaAnonymous Class
this refers toEnclosing classAnonymous class itself
StateNo state (stateless)Can have fields/state
Use caseFunctional interface onlyAny interface/abstract class
VerbosityConciseVerbose

09 Effectively Final – Lambda Variable Capture

🔑 Variables used inside a lambda must be final or effectively final (not reassigned after first assignment). Lambda captures the VALUE, not the reference.
int x = 10;                          // effectively final
Supplier<Integer> s = () -> x + 5;  // ✅ x not changed after this

int y = 10;
// y = 20;  // makes y NOT effectively final
// Supplier<Integer> s2 = () -> y + 5; // ❌ compile error

// Workaround using array or AtomicInteger
int[] counter = {0};
Runnable inc = () -> counter[0]++;   // ✅ array ref is final, contents mutable
inc.run(); inc.run();
System.out.println(counter[0]);      // 2

10 Method References

Shorthand for a lambda that simply calls an existing method. Syntax: ClassName::methodName

4 Types

// Type 1: Static Method Reference  →  ClassName::staticMethod
Function<String, Integer> parseInt  = Integer::parseInt;
Function<Double, Double>  abs       = Math::abs;
System.out.println(parseInt.apply("123"));   // 123

// Type 2: Instance Method of specific object  →  object::method
String prefix = "Hello";
Predicate<String> startsWith = prefix::startsWith;
System.out.println(startsWith.test("Hel"));   // false ("Hello".startsWith("Hel"))

// Type 3: Instance Method of arbitrary object  →  ClassName::instanceMethod
Function<String, String>  toUpper  = String::toUpperCase;
Function<String, Integer> length   = String::length;
Predicate<String>          isEmpty  = String::isEmpty;

List<String> names = List.of("alice","bob","charlie");
names.stream().map(String::toUpperCase).forEach(System.out::println);
// ALICE, BOB, CHARLIE

// Type 4: Constructor Reference  →  ClassName::new
Supplier<ArrayList<String>> listFactory = ArrayList::new;
Function<String, StringBuilder> sbFactory = StringBuilder::new;

ArrayList<String> list = listFactory.get();
StringBuilder sb = sbFactory.apply("initial");

▌ Part 3 — Stream API

11 What is a Stream?

A Stream is a sequence of elements from a source that supports sequential and parallel aggregate operations. Streams are lazy, not storage, and consumed once.

Source (Collection/Array) → filter() → map() → sorted() → limit() → collect() / forEach()
PropertyDetail
Not a data structureDoesn't store data — processes from source
Lazy evaluationIntermediate ops not executed until terminal op called
Consumed onceOnce closed, can't reuse — create new stream
Non-destructiveNever modifies original source
PipelineIntermediate ops return Stream; terminal ops return result

12 Stream Creation

import java.util.stream.*;

// 1. From Collection
List<String> list = List.of("a","b","c");
Stream<String> s1 = list.stream();
Stream<String> s2 = list.parallelStream();

// 2. From Array
Stream<String> s3 = Arrays.stream(new String[]{"x","y"});

// 3. Stream.of()
Stream<Integer> s4 = Stream.of(1, 2, 3, 4, 5);

// 4. Stream.iterate() — infinite stream
Stream<Integer> evens = Stream.iterate(0, n -> n + 2)
                               .limit(5);   // [0, 2, 4, 6, 8]

// 5. Stream.generate() — infinite with Supplier
Stream<Double> randoms = Stream.generate(Math::random)
                                .limit(3);

// 6. Primitive streams (avoid boxing overhead)
IntStream    ints  = IntStream.range(1, 6);     // [1,2,3,4,5]
IntStream    range = IntStream.rangeClosed(1,5); // [1,2,3,4,5]
LongStream   longs = LongStream.of(1L,2L,3L);
DoubleStream dubs  = DoubleStream.of(1.0,2.0);

// 7. Stream.empty()
Stream<String> empty = Stream.empty();

// 8. Stream.concat() — merge two streams
Stream<String> merged = Stream.concat(
    Stream.of("a","b"), Stream.of("c","d"));

13 Intermediate Operations

Return a new Stream. Lazy — only execute when a terminal op is called.

List<Integer> nums = List.of(5,3,8,1,3,7,2,8);

// filter(Predicate) — keep matching elements
nums.stream().filter(n -> n > 3)  // [5, 8, 7, 8]

// map(Function) — transform each element
nums.stream().map(n -> n * 2)      // [10,6,16,2,6,14,4,16]

// mapToInt / mapToLong / mapToDouble
IntStream is = nums.stream().mapToInt(Integer::intValue);

// distinct() — remove duplicates
nums.stream().distinct()          // [5,3,8,1,7,2]

// sorted() — natural order
nums.stream().sorted()             // [1,2,3,3,5,7,8,8]

// sorted(Comparator) — custom order
nums.stream().sorted(Comparator.reverseOrder()) // [8,8,7,5,3,3,2,1]

// limit(n) — take first n elements
nums.stream().limit(3)             // [5, 3, 8]

// skip(n) — skip first n elements
nums.stream().skip(5)              // [7, 2, 8]

// peek(Consumer) — debug without changing pipeline
nums.stream()
    .filter(n -> n > 3)
    .peek(n -> System.out.println("After filter: " + n))
    .map(n -> n * 2)
    .collect(Collectors.toList());

// takeWhile (Java 9+) — take while condition true, stop at first false
Stream.of(1,2,3,4,5).takeWhile(n -> n < 4)  // [1, 2, 3]

// dropWhile (Java 9+) — skip while condition true
Stream.of(1,2,3,4,5).dropWhile(n -> n < 4)  // [4, 5]

14 Terminal Operations

Trigger the stream pipeline and produce a result. Stream is consumed after this.

List<Integer> nums = List.of(1,2,3,4,5);

// forEach — consume each element
nums.stream().forEach(System.out::println);

// collect — accumulate into collection
List<Integer> list = nums.stream().collect(Collectors.toList());
Set<Integer>  set  = nums.stream().collect(Collectors.toSet());

// count
long count = nums.stream().filter(n -> n > 2).count();  // 3

// min / max
Optional<Integer> min = nums.stream().min(Integer::compareTo);  // 1
Optional<Integer> max = nums.stream().max(Integer::compareTo);  // 5

// sum / average — on primitive streams
int    sum = nums.stream().mapToInt(Integer::intValue).sum();
double avg = nums.stream().mapToInt(Integer::intValue).average().orElse(0);

// findFirst / findAny
Optional<Integer> first = nums.stream().filter(n->n>3).findFirst();  // 4
Optional<Integer> any   = nums.stream().filter(n->n>3).findAny();    // any of 4,5

// anyMatch / allMatch / noneMatch
boolean any5  = nums.stream().anyMatch(n -> n == 5);   // true
boolean allPos = nums.stream().allMatch(n -> n > 0);   // true
boolean none0  = nums.stream().noneMatch(n -> n == 0); // true

// toArray
Object[] arr  = nums.stream().toArray();
Integer[] arr2 = nums.stream().toArray(Integer[]::new);

15 map() vs flatMap() — Most Asked

📌 map() — transforms each element 1-to-1 → Stream<Stream<T>> if input is nested
flatMap() — transforms + flattens → Stream<T> (one level of nesting removed)
// map() — 1-to-1 transformation
List<String> words = List.of("Hello", "World");

// map returns Stream<String[]> — nested!
Stream<String[]> wrong = words.stream()
    .map(s -> s.split(""));

// flatMap — flatten Stream<String[]> into Stream<String>
List<String> chars = words.stream()
    .flatMap(s -> Arrays.stream(s.split("")))
    .distinct()
    .collect(Collectors.toList());
// [H, e, l, o, W, r, d]

// Nested list flattening
List<List<Integer>> nested = List.of(
    List.of(1, 2, 3),
    List.of(4, 5),
    List.of(6, 7, 8)
);

List<Integer> flat = nested.stream()
    .flatMap(Collection::stream)
    .collect(Collectors.toList());
// [1, 2, 3, 4, 5, 6, 7, 8]

// Real-world: get all emails from list of customers
List<String> allEmails = customers.stream()
    .flatMap(c -> c.getEmails().stream())
    .collect(Collectors.toList());

16 reduce() – Custom Aggregation

List<Integer> nums = List.of(1, 2, 3, 4, 5);

// reduce(identity, BinaryOperator) — always returns value
int sum = nums.stream().reduce(0, (Integer a, Integer b) -> a + b);
// = 0+1+2+3+4+5 = 15

int product = nums.stream().reduce(1, (a, b) -> a * b);  // 120

int max = nums.stream().reduce(Integer.MIN_VALUE, Integer::max);  // 5

// reduce(BinaryOperator) — returns Optional (no identity)
Optional<Integer> sumOpt = nums.stream().reduce((a, b) -> a + b);
sumOpt.ifPresent(System.out::println);   // 15

// String concat with reduce
String sentence = List.of("Java", "is", "awesome")
    .stream()
    .reduce("", (a, b) -> a + " " + b)
    .trim();   // "Java is awesome"

17 Collectors API

import java.util.stream.Collectors;

List<String> names = List.of("Alice","Bob","Charlie","Dave");

// toList / toSet / toUnmodifiableList
List<String> list  = names.stream().collect(Collectors.toList());
Set<String>  set   = names.stream().collect(Collectors.toSet());

// joining
String csv    = names.stream().collect(Collectors.joining(", "));
// "Alice, Bob, Charlie, Dave"

String pretty = names.stream().collect(Collectors.joining(", ", "[", "]"));
// "[Alice, Bob, Charlie, Dave]"

// counting
long cnt = names.stream().collect(Collectors.counting());  // 4

// summingInt / averagingInt
int    totalLen = names.stream().collect(Collectors.summingInt(String::length));
double avgLen   = names.stream().collect(Collectors.averagingInt(String::length));

// summarizingInt — all stats at once
IntSummaryStatistics stats = names.stream()
    .collect(Collectors.summarizingInt(String::length));
System.out.println(stats.getMax());    // 7 (Charlie)
System.out.println(stats.getMin());    // 3 (Bob)
System.out.println(stats.getAverage()); // 4.75

// toMap
Map<String,Integer> nameLen = names.stream()
    .collect(Collectors.toMap(
        n -> n,              // key
        String::length,      // value
        (v1, v2) -> v1       // merge fn (handle duplicates)
    ));
// {Alice=5, Bob=3, Charlie=7, Dave=4}

18 groupingBy & partitioningBy

List<String> names = List.of("Alice","Bob","Anna","Charlie","Brian");

// groupingBy — group by some classifier
Map<Character, List<String>> byFirstChar =
    names.stream().collect(Collectors.groupingBy(s -> s.charAt(0)));
// {A=[Alice, Anna], B=[Bob, Brian], C=[Charlie]}

// groupingBy with downstream collector
Map<Character, Long> countByFirst = names.stream()
    .collect(Collectors.groupingBy(
        s -> s.charAt(0),
        Collectors.counting()
    ));
// {A=2, B=2, C=1}

// groupingBy employees by department
Map<String, List<Employee>> byDept = employees.stream()
    .collect(Collectors.groupingBy(Employee::getDepartment));

// groupingBy with average salary per dept
Map<String, Double> avgSalByDept = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.averagingDouble(Employee::getSalary)
    ));

// partitioningBy — splits into true/false map
Map<Boolean, List<Integer>> partitioned =
    List.of(1,2,3,4,5,6).stream()
        .collect(Collectors.partitioningBy(n -> n % 2 == 0));
// {false=[1,3,5], true=[2,4,6]}

// partitioningBy employees above average salary
double avgSalary = employees.stream()
    .mapToDouble(Employee::getSalary).average().orElse(0);
Map<Boolean, List<Employee>> aboveBelow = employees.stream()
    .collect(Collectors.partitioningBy(e -> e.getSalary() > avgSalary));

19 Parallel Streams

// Create parallel stream
List<Integer> nums = IntStream.rangeClosed(1, 1_000_000)
    .boxed().collect(Collectors.toList());

// Sequential
long sum1 = nums.stream()
    .mapToLong(Integer::longValue).sum();

// Parallel — uses ForkJoinPool.commonPool()
long sum2 = nums.parallelStream()
    .mapToLong(Integer::longValue).sum();

// Convert sequential to parallel mid-pipeline
long sum3 = nums.stream()
    .parallel()   // switch to parallel
    .filter(n -> n % 2 == 0)
    .mapToLong(Integer::longValue)
    .sum();
⚠️ Parallel Stream Pitfalls:
1. NOT always faster — overhead for small datasets
2. Avoid stateful operations (sorted, distinct) — order not guaranteed
3. Avoid shared mutable state — race conditions
4. Use reduce/collect over forEach for parallel — forEach ordering unpredictable
Sequential StreamParallel Stream
ExecutionSingle threadForkJoinPool threads
OrderGuaranteedNot guaranteed
Use whenSmall data, ordered opsLarge data, independent ops
OverheadNoneThread coordination cost

20 Optional<T>

Container that may or may not hold a non-null value. Replaces null checks and avoids NullPointerException.

import java.util.Optional;

// Creating Optional
Optional<String> present  = Optional.of("Hello");       // NPE if null
Optional<String> nullable = Optional.ofNullable(null);   // safe
Optional<String> empty    = Optional.empty();

// Checking
present.isPresent();    // true
present.isEmpty();      // false (Java 11+)

// Getting value
present.get();            // "Hello" — throws NoSuchElementException if empty
nullable.orElse("default");          // "default" (always evaluated)
nullable.orElseGet(() -> "computed"); // lazy — only called if empty
nullable.orElseThrow(() -> new RuntimeException("Not found!"));

// Transformations
Optional<Integer> len = present.map(String::length);   // Optional[5]
Optional<String> upper = present.map(String::toUpperCase); // Optional[HELLO]
Optional<String> filtered = present.filter(s -> s.length() > 3); // Optional[Hello]

// flatMap — when function returns Optional
Optional<String> name = Optional.of("Alice");
Optional<String> upper2 = name.flatMap(s -> Optional.of(s.toUpperCase()));

// ifPresent / ifPresentOrElse (Java 9+)
present.ifPresent(System.out::println);   // Hello
nullable.ifPresentOrElse(
    System.out::println,
    () -> System.out.println("No value")   // No value
);

// or() — Java 9+: provide another Optional if empty
Optional<String> result = nullable.or(() -> Optional.of("fallback"));
✅ Best practice: Never use Optional.get() without checking isPresent(). Prefer orElse(), orElseGet(), or orElseThrow(). Never use Optional as method parameter or field — only as return type.

Q&A Recently Asked Interview Questions

Q1 What is a Functional Interface? Can it have more than one method?

A Functional Interface has exactly ONE abstract method. It CAN have multiple default and static methods — those don't count. The @FunctionalInterface annotation enforces this at compile time but is optional.

@FunctionalInterface
interface MyFI {
    void doWork();                 // ← the ONE abstract method
    default void log() {}         // ✅ allowed
    static void create() {}       // ✅ allowed
}
Q2 What is the difference between map() and flatMap()?

map() — one-to-one transformation. Returns Stream<Stream<T>> if the mapping function returns a Stream/array.

flatMap() — one-to-many + flatten. Unwraps the nested Stream into a single Stream<T>.

// map — nested result
Stream<String[]> mapped   = Stream.of("Hi there").map(s -> s.split(" "));

// flatMap — flat result
Stream<String>  flattened = Stream.of("Hi there")
    .flatMap(s -> Arrays.stream(s.split(" ")));   // [Hi, there]
Q3 Difference between findFirst() and findAny()?

findFirst() — always returns the first element in encounter order. Consistent in sequential AND parallel streams.

findAny() — returns any element. In sequential streams, usually the first. In parallel streams, whichever thread finishes first — non-deterministic but faster.

Use findAny() with parallel streams for better performance when you just need any match.

Q4 Are streams lazy? How does lazy evaluation work?

Yes — intermediate operations (filter, map, sorted) are lazy. They don't execute until a terminal operation is called. This allows optimizations like:

  • Short-circuit: findFirst() stops after finding first match — doesn't process rest
  • Fusion: JVM can merge multiple intermediate ops into one pass
Stream.of(1,2,3,4,5)
    .filter(n -> { System.out.print("f"+n+" "); return n > 2; })
    .findFirst();
// Prints: f1 f2 f3 ← stops after finding 3, never processes 4,5
Q5 Can a stream be reused?

No. A stream can only be consumed once. After a terminal operation, the stream is closed. Reusing it throws IllegalStateException: stream has already been operated upon or closed. Always create a new stream from the source.

Stream<Integer> s = List.of(1,2,3).stream();
s.forEach(System.out::println);  // ok
s.forEach(System.out::println);  // ❌ IllegalStateException
Q6 Difference between orElse() and orElseGet() in Optional?

orElse(T value) — always evaluates the argument, even if Optional has a value. Can cause unnecessary computation.

orElseGet(Supplier) — lazy — the Supplier is only called when Optional is empty.

Optional<String> opt = Optional.of("present");

opt.orElse(expensiveComputation());         // always calls expensiveComputation()
opt.orElseGet(() -> expensiveComputation()); // NOT called (Optional not empty)

Prefer orElseGet() when the default involves expensive operations.

Q7 What is the difference between Predicate.and() vs && in a lambda?

Both achieve the same result but Predicate.and() is composable and reusable:

Predicate<Integer> isEven = n -> n % 2 == 0;
Predicate<Integer> isPos  = n -> n > 0;

// Method 1: inline lambda with &&
list.stream().filter(n -> n % 2 == 0 && n > 0);

// Method 2: Predicate.and() — reusable, readable
list.stream().filter(isEven.and(isPos));

Q9 When should you NOT use parallel streams?
  • Small datasets — thread coordination overhead > benefit
  • Ordered operations — sorted(), distinct() need re-ordering
  • Shared mutable state — race conditions
  • I/O bound tasks — use CompletableFuture instead
  • ArrayList is good, LinkedList is bad — parallel splitting works poorly on LinkedList
Q10 What is the difference between Collection.stream() and Arrays.stream()?
// Collection.stream() — for any Collection
List<String> list = List.of("a","b");
Stream<String> s1 = list.stream();

// Arrays.stream() — for arrays; can create typed primitive streams
int[] arr = {1,2,3};
IntStream   s2 = Arrays.stream(arr);         // no boxing!
Stream<Integer> s3 = Arrays.stream(arr).boxed(); // box to Integer

// Arrays.stream also supports range:
IntStream sub = Arrays.stream(arr, 1, 3);   // elements at index 1,2
Q11 How to handle checked exceptions inside streams?

Lambda expressions cannot throw checked exceptions directly. Workarounds:

// Option 1: Wrap in try-catch inside lambda
list.stream().map(s -> {
    try { return Integer.parseInt(s); }
    catch (NumberFormatException e) { return 0; }
});

// Option 2: Wrapper method
private static <T,R> Function<T,R> wrap(ThrowingFunction<T,R> f) {
    return t -> { try { return f.apply(t); } catch (Exception e) { throw new RuntimeException(e); } };
}
list.stream().map(wrap(Files::readString));
Q12 What is Collectors.teeing() and when do you use it? (Java 12+)

teeing() applies two downstream collectors to the same stream and merges their results with a BiFunction.

// Find min and max in one pass
Map.Entry<Optional<Integer>, Optional<Integer>> minMax =
    Stream.of(3,1,4,1,5,9)
        .collect(Collectors.teeing(
            Collectors.minBy(Integer::compareTo),
            Collectors.maxBy(Integer::compareTo),
            Map::entry
        ));
System.out.println(minMax);   // Optional[1]=Optional[9]
Q13 Difference between peek() and forEach()?

peek() — intermediate operation. Returns a Stream. Used for debugging/logging without breaking the pipeline.

forEach() — terminal operation. Consumes the stream. No further chaining.

List.of(1,2,3).stream()
    .peek(n -> System.out.print("before: " + n + " "))
    .map(n -> n * 2)
    .peek(n -> System.out.print("after: " + n + " "))
    .forEach(n -> {});   // terminal needed to trigger pipeline
Q14 What is effectively final? Why does Java require it for lambdas?

A variable is effectively final if it is never reassigned after its initial assignment. Java requires this for lambda captures because:

  • Lambdas may execute later (deferred execution) — if the variable changes, the lambda would see inconsistent state.
  • In parallel streams, sharing mutable variables causes race conditions.
  • Java lambdas capture the value, not the reference (unlike C++ closures).
Q15 How does groupingBy work internally?

groupingBy(classifier) creates a Map<K, List<T>> where K is the result of the classifier function applied to each element. Elements with the same key are grouped into a List. You can add a downstream collector for further processing (count, sum, joining, etc.).

// Equivalent manual implementation
Map<Integer, List<String>> byLen = new HashMap<>();
for (String s : names) {
    byLen.computeIfAbsent(s.length(), k -> new ArrayList<>()).add(s);
}
// Equivalent stream:
Map<Integer, List<String>> byLenStream = names.stream()
    .collect(Collectors.groupingBy(String::length));

Q17 What is Supplier used for? Give a real-world scenario.

Supplier provides a value lazily — it's called only when needed. Real-world uses:

  • Optional.orElseGet(Supplier) — compute default only when empty
  • Lazy initialization — delay expensive object creation
  • Factory patterns — Supplier<Connection> connFactory = Connection::new
  • Logging — logger.debug(() -> buildExpensiveMessage())
Q18 What is the difference between Stream.of() and Arrays.stream() for arrays?
int[] arr = {1, 2, 3};

// Stream.of() — treats array as SINGLE element → Stream<int[]>
Stream<int[]> s1 = Stream.of(arr);    // 1 element: the array itself

// Arrays.stream() — streams EACH element → IntStream
IntStream s2 = Arrays.stream(arr);   // 3 elements: 1, 2, 3

// For Integer[] (object array) — both work element-wise
Integer[] arrObj = {1, 2, 3};
Stream.of(arrObj);        // Stream<Integer> — elements 1,2,3
Arrays.stream(arrObj);   // Stream<Integer> — same
Q19 What is Collectors.collectingAndThen()?

Applies a downstream collector and then applies a finisher function to the result. Useful for post-processing after collection.

// Collect to List then make it unmodifiable
List<String> immutable = names.stream()
    .collect(Collectors.collectingAndThen(
        Collectors.toList(),
        Collections::unmodifiableList
    ));

// Get Optional of max, then extract value
String longest = names.stream()
    .collect(Collectors.collectingAndThen(
        Collectors.maxBy(Comparator.comparingInt(String::length)),
        opt -> opt.orElse("none")
    ));

// Stream over values only
